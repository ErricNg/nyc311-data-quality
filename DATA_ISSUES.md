# Data issues found

- Data: NYC 311 service requests, 2026-09-01 to 2026-09-07
- Downloaded: 2026-10-01
- Rows: 71,830 | Columns: 44
- Note: the source dataset is updated daily, so a later download may differ.

## Checked and clean

- unique_key: 0 missing, 0 repeated IDs, 0 fully identical rows
- created_date: 0 missing, 0 unparseable, all within Sept 1-7
- closed_date: 0 unparseable values
- status vs closed_date: every Closed request has a closed_date (64,898 of 64,898)
- The 5,968 empty closed_date values (8.3%) all belong to requests that are not Closed (In Progress 4,013, Open 1,839, Assigned 83, Pending 33). Expected missingness, not an error.
- Columns with 0.0% missing (rounded to one decimal): unique_key, created_date, agency, agency_name, complaint_type, status, community_board, police_precinct, open_data_channel_type. borough, park_borough, police_precinct and open_data_channel_type contain placeholder text instead of empty cells (see issues 7 and 10).
- agency and agency_name: 14 distinct values each, 14 distinct pairs, so one-to-one (agency_name is redundant)
- latitude, longitude and location: empty on exactly the same 1,301 rows (70,529 rows have all three, 1,301 have none, 0 have only some)
- location: text like POINT (longitude latitude), longitude first. Matches latitude and longitude on all 70,529 rows that have a location (within 0.000001 degrees). Redundant copy.
- borough and park_borough: identical on all 71,830 rows (including "Unspecified" on the same 80 rows). park_borough is a redundant copy.
- city and complaint_type: 0 values with stray whitespace. city has no spelling variants (50 distinct before and after normalizing).
- incident_zip: 71,228 non-empty values, 0 fail the 5-digit format (602 rows, 0.8%, are empty). Format only: a well-formed ZIP is not proven to be a real one.
- latitude and longitude: all 70,529 non-empty values are numeric. Latitude 40.4997 to 40.9129, longitude -74.2540 to -73.7006. 0 values outside the loose NYC box (latitude 40.4 to 41.0, longitude -74.3 to -73.6). The box cannot catch a point that is inside the rectangle but outside the city.

## Observations (not errors)

- DOB: all 2,346 DOB requests have a closed_date, but only 1,536 are marked Closed (Open 692, Assigned 118). Median closed_date minus created_date by status: Closed about 2 days, Assigned about 12.5 days, Open exactly 0. closed_date equals resolution_action_updated_date in 1,402 of 1,536 Closed (91.3%), 115 of 118 Assigned (97.5%), 0 of 692 Open. Hypothesis: for Assigned DOB requests, closed_date may record the last action date, not a closure. NOT VERIFIED.
- Close times recorded to the minute: share of close times with 0 seconds is DEP 91.8%, DOB 65.4%, DOT 49.6%. These are the three highest agencies in the table. Chance alone would give about 1.7%. So minute-level recording is common across agencies, not unique to DEP.
- Because of this, many close times may be up to 59 seconds early. Only requests closed within the same minute they were created show up as a contradiction, which is why issue 2 is limited to 23 rows.
- closed_date has 41,038 distinct values among 65,862 non-empty rows, so many requests share an identical close timestamp. Cause unknown.
- Location columns: latitude, longitude and location are empty on the same 1,301 rows (1.8%). x_coordinate_state_plane is empty on 1,298 rows and y_coordinate_state_plane on 1,288. All five are empty together on 1,285 rows; the other 16 are issue 8.
- Missing coordinates do not imply an unknown borough: 1,225 of the 1,301 rows with no coordinates still have a real borough. Only 76 do not.
- police_precinct placeholder vs missing coordinates: only 412 rows have both. 889 rows have a placeholder precinct but coordinates, and 889 rows have no coordinates but a real precinct. The two problems are mostly separate. Cause unknown.
- city mixes boroughs (BROOKLYN, BRONX, QUEENS), neighborhoods (JAMAICA, ASTORIA, FLUSHING) and "NEW YORK" (the Manhattan mailing name). It is an address field, not a borough field: BROOKLYN is 22,030 in city but 23,495 in borough. city is 6.9% missing.
- incident_zip is empty on 602 rows (0.8%), fewer than the 1,301 rows with no coordinates.
- landmark is 29.7% missing and often repeated the street name in the first 10 rows (to verify).
- created_date has 61,337 distinct values among 71,830 rows; about 10,500 requests share a timestamp with another request.
- Censoring: requests created late in the week had less time to be closed than requests created early in the week. Any average time-to-close from this data is biased low for recent requests.

## Decisions so far

- Rows with closed_date before created_date (issues 2, 3, 4; 25 rows): FLAG. Do not fix or drop. We cannot tell which date is wrong, and dropping loses otherwise valid data.
- Empty closed_date on non-Closed requests: LEAVE. Missing is meaningful here.
- Issue 1, DOB Open rows (692): FLAG. closed_date equals created_date to the second in 692 of 692 rows, so the field looks unreliable for these rows (probable placeholder, not verified). Keep the original value, add a suspect flag, and exclude flagged rows from any time-to-close calculation.
- Issue 1, the other 272 rows: not decided. Candidate rule: compute time-to-close only where status is Closed.
- park_borough: DROP from the cleaned file. It is identical to borough on all 71,830 rows, so it adds nothing.
- Issue 9, complaint_type spelling: FIX in a new column complaint_type_clean (strip, lowercase, collapse repeated spaces). Keep the original column and keep agency, because an HPD "elevator" and a DOB "elevator" may still be different kinds of complaint.
- Issue 6, empty cells in the 9 sparse columns: LEAVE the values as they are (empty means "does not apply" or "not entered"). Whether to drop the nearly empty columns from the cleaned file is a Phase 3 decision.
- incident_zip and coordinates: no value cleaning needed. Only type conversion in the cleaning step (ZIP stays text, latitude and longitude become numbers).
- Issues 5, 7, 8 and 10: not decided yet. Candidate for 7 and 10: convert placeholder text to missing in the cleaned file so isna() works.
- Candidates to drop from the cleaned file, decide in Phase 3: agency_name (redundant with agency), location (redundant with latitude and longitude), park_facility_name (99.9% placeholder).

## Not pursued

- Remaining agencies in the per-agency 0-seconds table. DEP, DOB and DOT already show the pattern, so more rows would not change a decision.
